# Success criteria — Junior Consultants  
## From the Fedora Lane Core Pack

Use this while rehearsing Part 1 and Part 2.

| Dimension | Needs improvement | Meets expectations | Exceeds expectations |
|---|---|---|---|
| **Technical solution quality & completeness** | Incomplete, non-functional, or misses key requirements | Meets requirements; fully functional | High craftsmanship: clear docs, logical organization, thoughtful usability/maintainability extras |
| **Communication & rationale** | Can’t explain what was built or why | Clear what/why; technical benefits; tied to customer challenges | Trade-offs, alternatives considered, enterprise best practices |
| **Solution presentation & professionalism** | Confusing demo; inaccurate answers about own work | Professional, logical flow; confident accurate Q&A | Polished; anticipates questions during walkthrough |

### Practical bar for this repo

- Demo runs from README without secrets in Git  
- Every shown feature maps to a Core Pack challenge  
- Opening / walkthrough / value / closing hit the Core Pack timeboxes  
- Follow-up email ready within 2 days of the live call
